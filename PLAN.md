Phase 1 — Capture layer (Week 1)
Start with a tight Python loop: mss for fast cross-platform screenshots, imagehash for perceptual hashing (dHash). Store only frames where the Hamming distance from the last hash exceeds a threshold of ~8. Log the active window title and process name alongside every frame using pygetwindow on Windows / Quartz on Mac. Get this loop stable and efficient before touching anything else — it's the foundation everything else depends on.
Phase 2 — Processing pipeline (Week 2)
Spin up a concurrent.futures.ThreadPoolExecutor and push frames into it for OCR. pytesseract on the raw screenshot is noisy — build a simple cleaner that groups text by bounding box Y coordinate and merges lines within ~15px of each other. Every processed frame writes one row to SQLite: (timestamp, app_name, window_title, cleaned_text, frame_hash). This is your raw timeline — it needs to be queryable by time range, app, and text match.
Phase 3 — Embedding + query (Week 3)
Pull nomic-embed-text via ollama or sentence-transformers — runs on CPU, no GPU needed. Chunk the cleaned OCR text from each frame into semantic units (~200 tokens), embed each chunk, store in LanceDB with metadata pointing back to the SQLite row. The query path is: user types query → embed it → ANN search in LanceDB → retrieve top 10 chunks + their timestamps and app context → pass to Claude API → Claude returns an answer with citations like "you saw this at 3:42pm on Tuesday in Chrome."
Phase 4 — Privacy + UI (Week 4)
Blocklist approach for sensitive apps: before each capture, check if the active process name or window title matches a list (1password, bitwarden, chrome incognito, bank domains, etc.) and skip the frame entirely. For encryption, sqlcipher3 bindings wrap SQLite with AES-256. The Electron tray app runs the Python pipeline as a child process, communicating over stdin/stdout JSON-RPC. React frontend: a single search input, a results feed showing snippets with timestamps, and a date-range purge button.
Phase 5 — Polish + demo (Week 5)
Temporal reasoning in the query: before embedding the user's query, run a lightweight parse to detect time expressions ("last Tuesday", "this morning", "past week"), translate to a UNIX timestamp range, and pre-filter the LanceDB search to that window. Memory compression: a nightly job that groups raw frames older than 30 days by app session, summarises each session with Claude, stores the summary, and deletes the raw rows. Add Whisper as an optional toggle — runs faster-whisper on mic audio in parallel.
Biggest risk to manage: OCR throughput on older machines. Benchmark Tesseract on your hardware in week 1 — if it can't keep up at 5-second intervals, increase to 10 or 15 seconds, or only OCR frames that passed the hash diff check (which you're already doing). The frame drop mechanism is your safety valve.
This is genuinely a strong portfolio piece. The combination of real-time screen processing, local ML inference, and semantic retrieval is rare — and the privacy-first angle gives it a clear positioning story versus Rewind.
